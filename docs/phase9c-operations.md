# Private production operations

Viewers browse and play anonymously. The public Next.js process uses the playback reader and has no operator or migration credentials. The local dashboard remains available only in development with its existing loopback checks. Production administration uses private, fixed-command workers. See [.env.example](../.env.example) for variable names.

## Identity and privileges

Connect the worker launcher to an existing organizational identity provider. Use authorization code with PKCE for humans and a workload identity for the scheduler. The launcher passes a short-lived access token through a protected process environment. Keep its configuration, executable, database password, policy files and role assignments writable only by the infrastructure owner. Operators must have neither shell access to this process nor raw write credentials. A holder of raw database credentials can act outside the application authorization layer.

The verifier accepts RS256 access tokens with `typ=at+jwt`, a pinned SPKI public key, exact HTTPS issuer, single exact audience, subject, issue time and expiry. The maximum token age and lifetime are ten minutes. Human tokens must include MFA in `amr` and an `auth_time` within fifteen minutes. The identity provider controls the assurance of those claims. Configure distinct audiences for humans and jobs. Configure a stable deployment-owned subject-to-role JSON object, for example `{"operations-oncall":"responder"}`. Role claims supplied by tokens have no effect. Give each worker only the configuration for its own identity kind. On signing-key rotation, update the pinned verification key through the trusted configuration channel and obtain fresh tokens.

| Identity | Allowed operations |
|---|---|
| Auditor | Inspect registry and synchronization state |
| Editor | Add or edit pending source records and descriptive fields |
| Publisher | Approve a reviewed supplier package, enable a source, validate packages, run policy-constrained imports |
| Responder | Disable, remove or permanently revoke a source |
| Maintainer | Migrate approved data, roll back an import, apply schema migrations |
| Scheduled workload | Run the pinned supplier policy, validate pinned packages, inspect rights and checkpoints |

Human roles also have inspection access. Store licensing evidence in the private operator database. Successful mutations write the verified actor to append-only application audit events. Keep SQL audit inspection in a restricted DBA/audit plane. Credentialed database owners remain a privileged trust boundary. Limit audit-log exports to designated reviewers.

Use the existing `sources:database` and `sources:package` commands in the authenticated worker. Use a separate migrator worker for schema changes. Set `NODE_ENV=production` and `STREAMFRAME_REGISTRY_MODE=postgres`. The web process takes the verified-TLS read URL, TMDB read token, delivery origin and independent signing and geo keys. Keep PostgreSQL CA material in private configuration. The scheduler takes the write URL, job identity, TMDB token and immutable policy digest. Supply only role-specific secrets. Store tokens and passwords in a secret store or OS-protected service configuration. Avoid command-line tokens, shell history, logs, client bundles and shared .env files.

## Scheduled operations

Invoke `npm run sources:scheduled` from a private scheduler with a fresh workload token. A 15-minute interval is an initial operating choice. The supplier's own minimum interval still applies. Use a direct PostgreSQL connection or session-mode pool for the job. A session-level PostgreSQL lock rejects a concurrent scheduled invocation. Discovery uses the existing durable checkpoint lease and atomic publication/cursor transaction. A failed worker releases its connection lock and a replacement can take over an expired lease. Database or validation failures produce a nonzero exit. Have the scheduler retry with bounded backoff and alert after a repeated failure. Interrupting a read-only package validation can repeat that validation on retry.

Mount the approved `data/import-policy.local.json` read-only and configure the SHA-256 digest of its exact bytes in `STREAMFRAME_POLICY_SHA256`. Each preauthorized edition needs a `rightsSnapshot` generated by the exported `rightsSnapshot(candidate)` after a human reviews that publisher record and edition. A changed publisher, license, attribution, evidence or credit requirement invalidates the match. The snapshot covers the metadata supplied by the provider adapter. An offline publisher catalog still requires periodic human verification of the original evidence. Approve changed policy bytes out of band. The job cannot change policy pins or enroll a supplier.

Optionally mount up to 16 reviewed supplier manifests at `data/supplier-packages/<sha256>.json` and pass comma-separated digests through `STREAMFRAME_PACKAGE_DIGESTS`. The worker verifies the exact bytes and runs the existing TMDB, media, episode, subtitle and rights validators. This queue is validation-only. Package publication requires the publisher role; automatic discovery can publish only editions matching its pinned policy. Rights windows take effect at request time independently of the scheduler.

## Gateway and monitoring

Mount `createProductionGateway().handle` on a separate Node media host at the signed path, before all cache hits. Configure the exact HTTPS player and delivery origins, private S3 endpoint, region, bucket, and read-only service credentials. The authenticated edge must strip incoming geo headers and inject trusted replacements. Block direct public bucket, mirror and origin addresses. Use a separate staging writer. Use both a provider-side deny-public policy and least-privilege network/IAM restrictions. Every authorized MP4 range, HLS playlist, audio track, subtitle and segment checks a current approved registry row and edition revision. DB errors deny delivery. Plan capacity for a reader query per request before introducing a bounded revocation cache. Delete signed paths and query strings from edge, error-tracker and proxy logs.

Aggregate `media_requests` windows expose request and denial counts, upstream failures and response lengths. Feed these counters to a private log sink and alert on a sustained rise relative to normal traffic. Windows flush on a subsequent request after a minute or at 10,000 requests; short-lived workers may lose a partial window. Use provider request/status totals for complete traffic accounting. Compare reply lengths and `media_package_staged` bytes against actual provider egress and storage inventory. Staging totals include retries and response lengths can include interrupted transfers. Use provider budget alerts and a bandwidth ceiling before enabling real delivery. Record synthetic start, seek and resume results for both formats in staging to detect player/codec failures with successful HTTP responses.

Alert on `database_connection_failed`, `playback_registry_unavailable`, `scheduled_job_failed`, repeated `privileged_operation_denied`, nonzero package failures and any `license_window.expiringWithinWeek`. Review expired sources immediately. Collect counts and operation names. These events carry no viewer identity, IP, playback token or signed URL. Configure any external monitoring retention and access separately.

## Emergency procedure

1. Open the private responder worker with a fresh MFA-backed token. Run `npm run sources:database -- disable SOURCE_ID --apply` for a reversible suspension, or `npm run sources:database -- revoke SOURCE_ID "rights withdrawn" --apply` for a permanent tombstone.
2. Check the public playback response and retry a previously issued MP4 range and HLS segment. Both should be denied. Ask external hosts to withdraw legacy directly hosted editions. Bytes already delivered to a device cannot be recalled.
3. If an edge check was skipped or the signing key leaked, suspend the gateway, block origin access, rotate the shared delivery key on both services, and purge downstream caches. Reissue grants only after verification. For a compromised operator, remove the subject mapping, revoke sessions at the provider, stop in-flight workers and rotate any exposed worker credentials.
4. Retain the private audit sequence and aggregate incident timestamps. Review policy pins and source state with the rights owner before authorizing a replacement edition.

Before release, exercise a real IdP login and MFA, workload-token issuance, key rotation, denied direct-origin access, trusted country injection, cache behavior, revocation latency, full-length playback, monitoring delivery and long-session load against the selected providers. Local tests cover application behavior. Infrastructure verification needs a separately approved environment.
